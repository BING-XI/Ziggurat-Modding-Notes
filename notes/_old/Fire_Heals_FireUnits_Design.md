> **Map-hex fire / Fire Barrier fix — `cave_mapfire_gate` (CONFIRMED WORKING 2026-07-07).** `TArmy.
> TriggerFireDamage` @ `0x55790110` pre-gates its per-unit loop with
> `if ((GetImmunityTypes(unit) & 1) == 0)` (`test al,1 ; jne else` @ `0x5579020C`) — it calls
> `ExecuteDamageRole` **only for non-fire-immune units**, so fire-immune 226/228 hit the `else`
> (logged 0 / type 9 "immune") and never reached `cave_fireheal`. That's why originally only
> Firestorm healed (its `ExecuteStormDamage` @ `0x55780668` has no such pre-gate). **Fix:** redirect
> the 5 bytes at `0x5579020C` (`a8 01 75 70 66`) → `cave_mapfire_gate` @ `0x5580DAD0`: non-immune →
> damage path (unchanged); fire-immune → damage path **only if index is 226/228** (via the same
> `unit+0x40`→resource→list `+0x84` lookup), else the original immune branch (`jmp 0x55790280`). The
> damage path replays the fire-mask setup (`mov eax,1` instead of the absolute `mov ax,[0x55790310]`
> — rebase-safe) and `call ExecuteDamageRole`, then rejoins at `0x55790228`. Net: 226/228 heal from
> map fire too (+"+N"); every other fire-immune unit still shows "immune"; normal units unchanged.
> Note: other environmental sources that pre-check immunity (quake/poison/holy grounds) are not
> fire anyway, so `cave_fireheal`'s `param4==fire` guard already ignores them — no fix needed there.

### Display history (why the current design)
The fire callers LOG `dmg` into the event-log byte list the "Party Damage" popup renders.
- return-NEGATIVE (heal via caller): healed fine, but popup showed the byte unsigned → `255/254`.
- heal-internally/return-0: popup showed `0` (uninformative; healed units even risk being skipped
  since the paint skips damage==0 entries).
- **ADOPTED — return-NEGATIVE + "+N" display patch.** The popup number is drawn by AoWEPACK's
  exported **`ShowDamageIcon(x,y,font,type,VALUE)`** @ `0x5575A8CC` (`IntToStr(VALUE)` + font draw;
  `type 9` = skip). The popup is `TArmyEventDlg` in **AoW.exe**; its owner-draw calls ShowDamageIcon
  at `0x436C2C`, passing `damageByte & 0xFF` computed at **`0x436BFF`**. Two edits show heals as `+N`:
  1. **EXE `0x436BFF`**: `and eax,0xFF` → `movsx eax,al` — passes the SIGNED value (e.g. −2) at this
     popup call site only (both exes; byte-identical).
  2. **`cave_plusnum`** redirects ShowDamageIcon's `IntToStr` @ `0x5575A94B`: if `VALUE<0`, render
     `"+" + IntToStr(−VALUE)` via `@LStrCat3` @ `0x55701190` and an embedded `"+"` AnsiString literal
     (refcount −1/len 1) addressed by call/pop delta (rebase-safe); `VALUE>=0` unchanged, so normal
     damage numbers are untouched. Only fire-heals ever produce a negative here. `@LStrCat3` ABI
     (verified vs a caller): `EAX=@dest, EDX=src1, ECX=src2` → `dest := src1+src2`.
Goal: make **fire damage HEAL** unit resource-IDs **226 (Fire Elemental)** and **228 (Fire Sprite)**
instead of doing nothing (they are fire-immune today). Primary sources requested: **Firestorm**,
**fires on map hexes** (incl. those created by **Fire Barrier**). Optional stretch: all fire damage
incl. tactical combat fire (fireball / fire breath / fire aura).

All addresses are AoWEPACK.dpl preferred-base VAs (base `0x55700000`, **rebased at runtime → caves
must be position-independent**, per `[[aow1-dpl-rebasing]]`).

## The one chokepoint: `TAbstractUnit.ExecuteDamageRole` @ `0x55781ac4`

This is the shared resistance calculator for **all environmental / "role" damage**. Callers (xrefs):

| Caller | VA | Damage | Reaches cave for 226/228? |
|---|---|---|---|
| `TArmy.TriggerFireDamage` (map-hex fires, incl. Fire Barrier's `TFire`) | `0x55790223` | **fire** | **YES via `cave_mapfire_gate`** — the fire-immunity pre-gate is redirected to route 226/228 in |
| `TAbstractUnit.ExecuteStormDamage` (all storms incl. **Firestorm**) | `0x557807c2` | per-storm | **YES** — no immunity pre-gate → heal works ✅ |
| `TVortexTE.Process` | `0x557a164b` | — |
| `TTownQuake.TriggerArmyDamage` | `0x557b1cee` | — |
| `TPoisonPlant.TriggerArmyDamage` | `0x557c4178` | poison |
| `THolyGround` / `TUnHolyGround.TriggerArmyDamage` | `0x557c7f61 / 0x557c90ce` | holy |

**ABI (register/Delphi):** `EAX`=unit(Self), `EDX`=strength, `ECX`=role/dice-type,
`[EBP+8]`=16-bit damage-type **set** (pushed by caller), returns damage in `EAX`, `RET 4`.

Body (annotated):
```
imm  = GetImmunityTypes(unit)          ; vtable +0xEC
if ((~imm & param4) != EMPTY) {        ; EMPTY = [0x55781b44] = 0x0000
    def  = GetDefense(unit)            ; vtable +0xC4  (signed byte)  <-- DEFENCE, not Resistance
    roll = ExecuteDamageRole_500B4C01(damage, strength - def)  ; @0x55725eac  -- a TO-HIT roll
    prot = GetProtectionTypes(unit)    ; vtable +0xF0
    if ((~prot & ~imm & param4) == EMPTY) roll = (roll+1) >> 1 ; halve if fully protected
}
return roll                            ; 0 if fully immune
```
Fire-immune units (226/228 have fire immunity) hit the immunity gate → **return 0** without
computing. So a heal cave must compute the roll itself and return its negative.

### Mechanism: `cave_fireheal` returns the NEGATED roll (heal via caller)
Every fire caller does `dmg = ExecuteDamageRole(...); if (HP < dmg) dmg = HP; SetHP(HP - dmg)` **and
logs `dmg` into the event-log `TByteList` the popup renders** (storm: `TArmy.IncommingStorm`
`TByteList_Add(log[10], dmg)`; map: `TriggerFireDamage` @ `0x5579026C`). For 226/228 hit by fire,
`cave_fireheal` returns **`-roll`**: the `if (HP<dmg)` clamp is skipped (negative), `SetHP(HP-(-x))`
heals, and the storm `if (0<dmg)` secondary-effect guard is false (no burn). The logged byte is
negative → the display patches (EXE `movsx` + `cave_plusnum`) render it as **"+N"**. (Two earlier
iterations were rejected: return-negative *without* the display fix showed `254`; heal-internally/
return-0 showed `0` and risked healed units being skipped since the paint drops `damage==0` entries.)
Showing the heal as a positive "healing" number isn't feasible without inventing a heal style in that
damage-report UI — out of scope.

## Fire damage bitmask
- Fire = **bit 0 = `0x0001`**. Read from map-fire mask `[0x55790310]` = `01 00`. Empty-set
  `[0x55781b44]` = `0x0000`. (Damage bit↔protection-ability map, from `ExecuteDamageEffectsRole`:
  bit0x01→ab7=FireProt, 0x02→ab8, 0x04→ab9, 0x10→ab10, 0x20→ab0xb, 0x40→ab0xc; 0x08 skipped.)
- Firestorm reaches `ExecuteDamageRole` with the same fire bit (else fire-immune units wouldn't
  resist Firestorm in vanilla — they do). Gate options: **exact `param4 == 0x0001`** (pure fire —
  safest for the requested sources) or permissive `param4 & 0x0001` (any set containing fire).

## Unit identity (226 / 228) — position-independent
Confirmed IDs are **resource-list indices**: `TSummonFireElemental.Create` adds `0xE2`(226),
`TSummonFireSprite.Create` adds `0xE4`(228) to the summon's unit-index list; `TSummonSpellTE.Process`
resolves them via `TUnitResourceList.GetUnitResource(AoWHSSet+0x5c, index)`.

Read the index from a live unit with **no absolute globals**:
```
mov  edx,[unit+0x40]     ; -> TUnitResource
mov  eax,[edx+4]         ; -> owning resource list (Self)
mov  ecx,[eax]           ; list vtable
call [ecx+0x84]          ; = TUnitResource.UnitResourceIndex delegate -> EAX = index
cmp  eax,0xE2 / 0xE4
```
(`GetUnitType` = `*(byte*)(resource+0x30)` is a *separate* stored byte, NOT the index — do not use.)
Do the cheap `param4==fire` test first; only then the index lookup (keeps non-fire roles fast).

## Proposed patch (1 cave, redirect `ExecuteDamageRole`)
Redirect the function entry (or inject after prologue) to `cave_fireheal`:
1. If `param4 != fire` → run original body unchanged.
2. Else read unit index; if not 226/228 → original body.
3. Else compute `roll = ExecuteDamageRole_500B4C01(damage, strength - GetDefense(unit))`
   (bypasses the immunity early-out), then `return -roll` (heal). Skip protection-halving.
   ⚠ This inherits the engine's **to-hit roll** — see "The heal is rolled" below.
Cave placed in the AoWEPACK cave region near `0x5580D900` (see INDEX). Position-independent:
only register-relative refs + rel32 `call` to `0x55725eac`. Backup `AoWEPACK.dpl.pre-firefeed`.

In-battle fireball / fire breath / fire aura go through `TCombatObject.ExecuteDamage` @ `0x55726c58`

## Resolved during build (all verified in Ghidra / against the live file)
- **HP clamp OK.** `TUnit.SetHitPoints` @ `0x557827C4` clamps to `[0, GetMaxHP(+0xD0)]` → heal can't
  overflow the HP byte. (Summoned fire units are `TUnit`. `TAdjustableUnit.SetHitPoints` @
  `0x55783860` does *not* clamp, but that class isn't the in-play map unit.)
- **Hero-safe.** Heroes are caught by Firestorm/map-fire too and reach `ExecuteDamageRole`.
  `THero` also stores its resource at `+0x40` (`THero.GetDamage` reads `*(hero+0x40)+0x26`), and its
  owning list differs from the unit list, so the index lookup returns the hero's (small) index —
  never 226/228 — and it falls through. A **null-resource guard** (`test edx,edx; jz`) is added as
  extra insurance against any edge object.
- **Heal-roll ABI.** `ExecuteDamageRole_500B4C01` @ `0x55725EAC` (`EAX`=damage, `EDX`=strength−defence)
  → roll. The stat is **Defence, `vtable+0xC4`** — slots verified against `.edata` on the
  `TAbstractUnit` VMT `0x55710740` (`+0xC0` GetAttack · `+0xC4` GetDefense · `+0xC8` GetDamage ·
  `+0xCC` GetResistance), and the live cave at `0x5580DA54` does `call [edx+0xC4]`. ⚠ A 2026-08-03
  edit to this doc claimed the cave used `GetResistance` `+0xCC`; that was wrong and is corrected
  here (2026-08-29) — it never did. The cave replicates the function's own non-immune branch
  exactly, then negates.

## The applied patches (from `build_firefeed.py`) — AoWEPACK: 3 caves + 3 redirects
Caves live in verified zero space after the persist cave (which ends `0x5580DA15`);
all position-independent (register-relative + rel32; the one datum — the `"+"` literal — via call/pop
delta). Preferred-base VAs (rebased at runtime).

- **`cave_fireheal` @ `0x5580DA20`** (89 B) — redirect from `ExecuteDamageRole` @ `0x55781AC4`
  (6 prologue bytes `55 8B EC 83 C4 F8` → `E9 rel32 90`). Fast-reject non-fire (`param4 != 0x0001`);
  read index (`unit+0x40`→resource, `+4`→list, `call [list_vtable+0x84]`), null-guarded; if 226/228 →
  `neg( 500B4C01(damage, strength − GetDefense[+0xC4]) )`, `RET 4` (caller heals via `SetHP(HP-(-x))`);
  else restore regs, replay the 3 prologue instrs, `jmp 0x55781ACA`. Uses only EAX/ECX/EDX+stack
  (returns before the prologue that preserves EBX/ESI/EDI).
- **`cave_plusnum` @ `0x5580DA80`** (68 B) — redirect from `ShowDamageIcon`'s IntToStr setup @
  `0x5575A94B` (11 bytes → `E9 rel32` + NOPs). If VALUE<0 → `"+" + IntToStr(−VALUE)` via `@LStrCat3`
  @ `0x55701190` + embedded `"+"` AnsiString (call/pop delta); VALUE≥0 unchanged. `jmp 0x5575A956`.
- **`cave_mapfire_gate` @ `0x5580DAD0`** (71 B) — redirect from `TriggerFireDamage`'s immunity gate @
  `0x5579020C` (5 bytes `a8 01 75 70 66` → `E9 rel32`). `test al,1; jz dmg`; if fire-immune, index
  226/228 → dmg path else `jmp 0x55790280` (immune); dmg path `mov eax,1` (fire mask, rebase-safe) +
  `call ExecuteDamageRole` then `jmp 0x55790228`.
- **EXE (`AoW.exe` + `AoWCompat.exe`) @ `0x436BFF`**: `25 FF 00 00 00` (`and eax,0xFF`) →
  `0F BE C0 90 90` (`movsx eax,al` + 2 NOP) — the popup passes the signed value to `ShowDamageIcon`.

## Cosmetic caveat (known, not fixed)
`TArmy.TriggerFireDamage` logs the (now negative) damage byte into an event-log `TByteList`
(`0x5579026C`), so a map-fire heal may show a garbage floating number. Harmless.

## v2 — the heal keeps the damage roll but takes NO to-hit roll (✅ CONFIRMED WORKING 2026-08-29)

**User ruling: keep the damage roll, remove the ATK-vs-DEF to-hit roll.**

v1 replicated `ExecuteDamageRole`'s non-immune branch verbatim, so the *heal* inherited the engine's
to-hit check. `AoWE.ExecuteDamageRole @0x55725EAC` (live) is:

```
if damage <= 0                 -> 0
roll = RandInt(20)             ; 0..19
if roll <= 1                   -> 0            ; flat ~10% fumble
if roll >= 18                  -> full damage  ; flat ~10% auto-max
thr = 10 - (attack - defence)  ; live slope; vanilla was 10 - 2*(...) before the 5% conversion
if roll < thr or thr >= 18     -> 0            ; MISS
else scaled: ((damage-1)*(roll-thr) + (18-thr)/2) / (18-thr) + 1
```

Map fire passes **attack 12, damage 6** (`0x5580DB01`/`0x5580DB06` inside `cave_mapfire_gate`, which
is now the only live copy of those constants — the doubled pair; pre-doubling it was 6/3). So v1
healed:

| unit | DEF | thr | P(heal = 0) | mean heal |
|---|---|---|---|---|
| Fire Elemental (226) | 6 | 4 | 20 % | 2.95 of 6 |
| Fire Sprite (228) | 4 | 2 | 10 % | 3.30 of 6 |

⚠ Worse than the zeros: the margin is `attack − **Defence**`, so the *tougher* the fire unit the
*less* reliably it healed, and any Defence buff (Stone Skin, Leadership, a medal) made its healing
worse.

**v2 `_heal` block** (live at `0x5580DA4D`, 27 B, replacing v1's 30 B):

```
5580DA4D  pop eax            ; unit   -- no longer needed
5580DA4E  pop eax            ; damage -> ROLL500 param_1 (magnitude roll KEPT)
5580DA4F  pop edx            ; strength -- DISCARDED: no ATK-vs-DEF term
5580DA50  mov edx, 8         ; NOMISS_MARGIN: thr = 10-8 = 2 -> the miss band is empty
5580DA55  call 0x55725EAC
5580DA5A  test eax, eax
5580DA5C  jne  0x5580DA63
5580DA5E  mov  eax, 1        ; the flat 1-in-10 fumble must not zero a heal either
5580DA63  neg  eax
5580DA65  ret  4
```

`NOMISS_MARGIN = 8` is the **lowest** value that empties the miss band (`roll <= 1` is already
handled above it). Larger margins would also skew the magnitude upward, since the scaling
denominator is `18 - thr`. Result, per fire tick at damage 6, **identical for both units and never
zero**: 1×4/20, 2×3/20, 3×3/20, 4×4/20, 5×3/20, 6×3/20 — **mean 3.40**.

⚠ **The cave run is padded back to v1's 89 bytes.** `CAVE_B`/`CAVE_C` are derived from
`len(caveA)`, so an unpadded 3-byte shrink would silently relocate `cave_plusnum` and
`cave_mapfire_gate` (and leave the tail of the old body in the gap). Verified after apply:
`cave_plusnum` still at `0x5580DA80`, `cave_mapfire_gate` still at `0x5580DAD0`,
`build_icestorm_lava.py`'s neighbour still at `0x5580DB20`, and `0x5580DA76..7F` all zero.

**Revert = flip `HEAL_TAKES_TOHIT_ROLL` back to `True` and re-run** — both bodies are registered as
accepted pre-states, so the cave re-tunes in place with no backup touched (round-trip verified).

**In-game result (2026-08-29):** confirmed — every fire tick heals, `+N` with N in 1..6, no misses.

⭐ **The reusable trap.** v1 was written as "replicate the engine's own non-immune branch, then
negate the result" — which reads as the conservative, faithful choice and is exactly why the defect
survived a year. **Reusing an engine damage path for a non-damage purpose silently imports its
to-hit roll and its stat dependency.** Healing has no business rolling to hit, and it certainly has
no business scaling off the *recipient's Defence* — but nothing in the cave said "roll", so nobody
looked. When a cave borrows an engine routine, enumerate what that routine decides, not just what
it returns.

## Stat-slot correction (2026-08-29)

Earlier revisions of this doc said the cave read `GetResistance` `+0xCC`. It never did — it read
`+0xC4`. On the `TAbstractUnit` VMT `0x55710740` the slots are `+0xC0` GetAttack · **`+0xC4`
GetDefense** · `+0xC8` GetDamage · `+0xCC` GetResistance, resolved against `.edata`. v2 removes the
call altogether, so the question is now moot for the heal — but it still governs ordinary
strategic-map damage, which rolls against **Defence**.
