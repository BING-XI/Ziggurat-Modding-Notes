## 1. Data model

### TSpell (registry entry, via `TSpellControl.GetSpell(*(AoWHSSet+0x84), id)` @0x55779AC8)
| Offset | Type | Meaning |
|---|---|---|
| +0x10 | int | spell ID (self) |
| +0x14 | int | base mana cost |
| +0x18 | int | **research cost** (research points) |
| +0x20 | byte | sphere |
| +0x21 | byte | research tier 1–4 (0 = not researchable) |
| +0x22 | byte | category (mask bit; research uses categories 0,1,2) |
| +0x30 | int | AI value (used to weight AI research choice) |
| vmt+0x64 | fn | enabled/valid predicate (checked before a spell counts) |

**Sphere IDs** (from `T*Node.GetMagicSphere`): 0=Cosmos, 1=Life, 2=Death, 3=Earth, 4=Air,
5=Fire, 6=Water. Secret-sphere spells carry a sphere id no leader ever has picks in, so they
never pass the picks gate (see §3).

### TPlayerMagicControl (player+0x54)
| Offset | Meaning |
|---|---|
| +0x10 | TPlayer back-ref |
| +0x24 | mana pool |
| +0x2c | research % of power income (0–100, set via ChangePowerSettings TE) |
| +0x30 | TIntegerList of **researched spell IDs** (serialized in ReadWrite) |
| +0x34 | **current research spell ID** (0 = none) |
| +0x38 | **research points remaining** for current spell |

### TLeader
- `+0xa0` = sphere-pick list (byte per pick; a leader with Fire 3 has three `5` bytes).
- `GetSpherePicks(sphere)` @0x5578B17C: **sphere 0 (Cosmos) hard-returns 4**; otherwise counts
  occurrences of the sphere id in the pick list.

## 3. `ValidResearchSpell` — the complete rule set

A spell is researchable iff **all** of:

1. **Picks gate:** `spell.tier ≤ GetSpherePicks(spell.sphere)`. Cosmos ⇒ always 4 ⇒ every tier;
   secret sphere ⇒ 0 picks ⇒ never.
2. **Not already researched** (`+0x30` list IndexOf).
3. **Tier-ladder gate (per sphere):** count researched spells *of the same sphere* by tier
   (only tier > 0, only spells passing `vmt+0x64`). Max unlocked tier starts at 1 and increments
   while `count[tier] ≥ 2` (up to 4). Spell valid iff `spell.tier ≤ maxUnlocked`.
   → confirms "2 spells of tier N in a sphere unlock tier N+1 **of that sphere**".
   Cosmos has its own ladder like any sphere.
4. Quirk: if `AoWEngine+0x6e` ≠ 0 the ladder result is overridden to **2** (tiers 1–2 always
   open, 3–4 never). Flag not fully traced; almost certainly the demo/unregistered-version cap
   (`RegisteredVersion` machinery). Irrelevant for registered installs.

Opposed-sphere restrictions live entirely in **sphere picking** (`TLeader.CanAddSphere`
@0x5578B1F8), not in research (the user has already softened those separately).

## 4. `NewTurn` — freebies and progress

1. **Day 1 only** (map+0x174 == 1, active player, and not (map+0x11a==1 with a pre-seeded
   researched list)): for each category 0,1,2 → collect all **tier-1** spells of that category
   whose sphere is Cosmos or has ≥1 pick, and grant **one at random** (direct list Add — does
   NOT go through ExecuteSpellResearched). = the three free starting spells.
2. **Progress:** if +0x34 set and not already researched: `+0x38 -= GetNetPowerToResearch()`.
   On ≤ 0: negative overshoot is refunded into mana (+0x24), a TPlayerMagicEventLog(type 0,
   spellID) entry is added (popup shown if local human), then `ExecuteSpellResearched` @call
   site **0x5577CDC4**.
   If nothing is being researched, the research share of power is converted to mana instead.
3. Then mana income/upkeep settlement.

## 6. Design — "Sphere-tier research" (SPECULATIVE, user-approved direction)

User goal: the research picker shows **one entry per (sphere, tier)** — sphere icon, title like
"Fire Sphere II", the member spells listed — visually distinct from the cast picker, and
researching it grants all spells of that tier. Two coupled layers:

**Layer 1 — mechanics (DLL, AoWEPACK):**
- **Grant cave:** repoint `call ExecuteSpellResearched` @**0x5577CDC4** (NewTurn completion site
  only): resolve finished spell → (sphere,tier); loop registry; every same-sphere+tier spell with
  category ∈ {0,1,2}, `vmt+0x64` true, not researched → `ExecuteSpellResearched(id)`. Tomes
  (TItem.ExecuteUse) and day-1 freebies untouched. Deterministic in NewTurn ⇒ MP/save safe. AI
  unchanged (its weighted pick becomes a tier pick). 2-per-tier ladder auto-satisfies.
- **Cost cave:** hook `ExecuteResearchSpell` @0x5577D569 (`mov eax,[eax+0x18]`): +0x38 = **sum of
  research costs of still-unresearched same-sphere+tier spells**. Turn counters read +0x38 ⇒ all
  displays follow automatically. Partial tiers (day-1 freebies) show reduced remaining cost.

**Layer 2 — presentation (EXE, AoW.exe + AoWCompat.exe):**
1. **Grouping cave** at the research branch (after SortOnLevel @0x42EFA8): compact the TSpellList
   to the first spell per (sphere,tier), ordered sphere-then-tier (same in-place compaction idiom
   as `cave_bookfilter` @0x60C0A8, which these very sites already route through for cast modes).
   ≤ ~25 entries ⇒ shorter book than vanilla.
2. **FillSlot research override**: entry hook in 0x42E8E0 — when mode ∈ {2,3} jump to cave:
   - `SxSpell` ← "{SphereName} Sphere {tier}" (RStr table @0x45E034 + IntToStr + LStrCatN — all
     thunks already used inside FillSlot);
   - `SxClass` ← "N spells" (or tier numeral);
   - `SxCost` ← Format(summed remaining research cost);
   - `SxMemo` ← member spell names: memo's own TStringList at `TAOWMemo+0x118` — Clear + `Add`
     per name (self-refreshing Add @vmt+0x34; reusable found in the combat-log work);
   - dim-when-researching logic kept (it's mode-2 code already).
3. **SpellIconDraw research branch**: mode ∈ {2,3} → draw GenericI[sphere-icon] instead of the
   spell's sequence-10 icon (8-byte id→index table: 0,27,30,33,36,42,39,0). Draw primitive =
   whatever default TAOWImage/ILB show uses (same call family the Sel-row/BookWin frames use;
   resolve the exact TInterfaceIL show export in aowInt/ILPACK at implementation time). Cosmos
   fallback: keep the representative spell's own icon (no Cosmos sphere icon exists).
4. Both exes patched identically; new caves go in the existing `.sc` section after
   `cave_bookfilter` (@0x60C0A8+, check free space) or a new section.
5. **Optional polish, same string builder:** "currently researching" surfaces — the book's
   ResearchPage (ResearchName/Icn/Memo, ~0x42FC0F area), TMagicWin's research panel
   (@0x42D1AD area), and the NewTurnDlg "Research new spell" prompt — currently name the single
   spell being researched. v1 can leave them (they'd show the representative spell's name);
   retitling them "Fire Sphere II" is the same cave logic applied at 2–3 more label sites.

Danger points / honest unknowns:
- The TInterfaceIL draw call for step 3 isn't pinned down yet (small RE task; the primitive
  demonstrably exists — every ILB-backed control uses it).
- FillSlot's research override replaces ~5 label writes — the cave is bigger than our usual
  (~250–350 bytes), but purely exe-side (fixed base, absolute addresses allowed).
- MP: peers need the patched DLL (norm for this mod); the exe UI layer is cosmetic per-client.

**Design decisions (RESOLVED by user 2026-07-18):**
1. Cost model: **flat per-tier ladder 100/200/400/800** (not summed member costs).
2. Cosmos: included as tier entries (keeps its own ladder; day-1 grant avoids it when possible).
3. Tomes: still grant a single spell.
4. Title: "**Fire I**" — sphere name + **Roman numeral** (sphere names from the RStr table, so
   non-English installs stay correct).
5. Day-1: instead of 3 random spells, **one full tier-1 sphere** (random among picked spheres,
   Cosmos only if the leader somehow has no picks).

### v7.4 (2026-07-18): first-open offset — self-healing layout via DlgUpdate
v7.3 still mis-laid the FIRST open: titles ~14px high (= the book window's BorderHeight),
because the first population runs BEFORE the page panel is absolutized — cave_layout's
"page.abs + ytab" was border-short, and nothing repaints until the next population (the user
observed a background battle event fixing it mid-display: events → repopulate → repaint).
Fix: **cave_dlgupd** @ entry-hook on `TSpellBook.DlgUpdate` @**0x431270** (orig bytes
`53 8B D8 8B 83`, per-tick OnUpdate of the Dlg): when the Dlg is visible and
`[S1Pnl+0x88] != [page+0x88] + ytab[mode][0]`, call the population fn **0x42EF14** — it
re-runs cave_layout with the now-valid page position and repaints via the SetGText
invalidations. Converges to a no-op tick check; also self-heals any future external
disturbance (the battle case) in ≤1 tick, for both cast and research tables.

### v7.3 (2026-07-18): first-open pitch fix — write Alignment.TopOffset too
v7.2 laid out at vanilla pitch on the FIRST book open only. Cause: the S-panels have
**Alignment ahTop with TopOffset = the DFM Ys** ([pnl+0xD4] alignment object, TopOffset at
**+0x20**; height case decoded in ReAlign @0x59803274: `Y = parent.h×TopOffPct/100 + TopOffset`).
The first Show runs ReAlign → +0x88 rewritten from TopOffset (page-relative) → the absolutize
pass (the +0xA4 flag's job) re-bases it → vanilla positions, clobbering the population-time
values. Later opens don't re-run ReAlign, so cave_layout's values held. Fix: cave_layout writes
BOTH — `[[pnl+0xD4]+0x20] = ytab[i]` (so any ReAlign recomputes to OUR layout) and the absolute
`[pnl+0x88]` (for draws before any ReAlign). This also resolves the long-standing rel-vs-abs
mystery: DFM/ReAlign write RELATIVE coords into +0x84/+0x88 and a separate pass absolutizes
them in place, gated by +0xA4.

### v7.2 (2026-07-18): CRASH FIX — panel parent field is +0xCC, not +0x10C
v7.1 crashed on every book population (AV @0x61163B in cave_layout, read of 0x88 = nil+0x88;
surfaced via the event-log popup path "OnExecuteEventLog (TAoWMapControl)"). Cause:
**+0x10C is the CONTROL-level AOWWindow/parent field** (valid on TAOWImage — where it was
proven) but **panels are window-class objects whose parent is [obj+0xCC]** (TAoWComponent
field; ReAlign nil-checks it and reads the parent's +0x7C width through it). cave_layout now
uses [pnl+0xCC] with nil guards on both the panel and its parent.
